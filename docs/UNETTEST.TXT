UNETTEST.EXE - Universal network DLL smoke test

Purpose
  Exercises a UNET network DLL (UNETESP.DLL for Sprinter-WiFi, or a UNETRTL.DLL
  for the RTL8019A card) through libman. Because every step goes through the
  DLL, the same tool validates either backend - the network card is chosen by
  the DLL name, not by rebuilding.

  UNETTEST is a diagnostic tool. It is shipped on the floppy image but not in
  the ZIP package.

  Note: the shipped UNETESP.DLL is built for ESP-AT 2.2.2 only (trigger-8
  receive, no 2.2.1 fallback). Its library name reads "UNET ESP 2.2.2", and
  NETINIT fails with status 4 if NETUP brought the link up on 2.2.1 firmware.
  A UNETRTL.DLL (RTL8019A) would be firmware-independent.

Usage
  UNETTEST [-d FILE.DLL] [-u udpport] [host [port]]

  -d FILE.DLL   Load this DLL instead of the default UNETESP.DLL. The name is
                used exactly as typed and may include a path
                (e.g. -d C:\WIFI\UNETESP.DLL).
  -u udpport    Run the UDP exercise (UDPOPEN/SEND/RECV against a datagram
                echo server) instead of the TCP one. Requires a UDP echo
                service listening at host:udpport (see tools/dev/udp_echo.py
                in the RTL8019A sibling project).
  host          Host name or IP address to test (default example.com).
  port          TCP port for the connect/send/receive step (default 80),
                unused when -u is given.

  Flags may appear in any order but must precede host. An unknown flag, or
  -d/-u without their required argument, prints this usage line and exits
  with status 1.

DLL search order
  Without -d, UNETTEST first looks for UNETESP.DLL in the directory that holds
  UNETTEST.EXE (via DSS APPINFO), then falls back to the current directory. So
  it works whether you run it from the install directory or through PATH from
  elsewhere. With -d the given name/path is used as-is, with no directory
  search.

  If the DLL cannot be loaded, UNETTEST prints the reason on the line after
  "Cannot load DLL:", for example:
    DLL file not found (code 3)         - not in the EXE dir nor current dir
    out of DSS memory (code 30)         - no free page for the DLL
    DLL read/seek error (code nn)       - I/O error reading the file
    not an L0/L1 DLL (bad file format)  - the file is not a libman DLL
    DLL refused to start (wrong window?)- the DLL's INIT hook rejected the load
    DSS could not map the DLL page      - SETWIN failed before INIT was called
  The "code" value is the raw DSS error (3 = file not found, 4 = path not
  found, 16 = invalid filename, 30 = no free memory).

Examples
  UNETTEST example.com
  UNETTEST -d UNETRTL.DLL 192.168.1.10 80
  UNETTEST example.com 80
  UNETTEST -u 9000 192.168.1.20

Behavior
  Brings up nothing itself - run NETUP (Sprinter-WiFi) or NETCFG -i / IFUP
  (RTL) first. UNETTEST then loads the DLL into window 1 and walks the API:
  library info, capabilities, network status, NETINIT, station IP, host
  resolve (may report "unsupported" on firmware/emulator without CIPDOMAIN),
  and ping. From there it either runs the TCP exercise - connect, an HTTP HEAD
  request and a short reply read - or, with -u, the UDP exercise: UDPOPEN,
  SEND one probe datagram, then RECV until an echo arrives (or up to 3
  timeouts). A byte-for-byte mismatch is reported as "udp echo MISMATCH"
  rather than a truncated/partial transfer, since a datagram is delivered
  intact or not at all. Either path ends with close and unload. It prints each
  result so a failing step is easy to spot.
  Before SETOPT it also verifies ABI 0x0100 and the mandatory TCP capability.
  If these are invalid, it prints the loaded L1 image sizes plus the relocated
  GETCAPS bytes and exits instead of jumping farther through a damaged DLL.

Exit status
  0  The full sequence completed (including a backend that reports UDP
     unsupported with -u: this is a capability gap, not a failure).
  1  Invalid command line.
  2  Network hardware not found, or the DLL could not be loaded.
  3  ESP/driver communication, connect, send or UDPOPEN error.
  4  Network not configured - run NETUP (or NETCFG -i / IFUP) first.

Notes
  The full DLL contract (function numbers, register ABI, error and capability
  codes, window and buffer rules) is documented in UNETAPI.TXT.
